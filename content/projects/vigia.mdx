## El problema

El código se mueve más rápido que la documentación: un rename de una función deja los docs
apuntando a un nombre que ya no existe, y nadie se entera hasta que un dev copia el snippet
viejo. El patrón — revisar docs a mano después de cada cambio — no escala, y la deuda de docs
obsoletas se acumula en silencio.

Vigia convierte la detección de docs obsoletas en un diff automático: extrae los símbolos del
código, encuentra las referencias que quedaron stale y abre la corrección.

## El enfoque

Un snapshot de repo committed, un extractor determinista y una regla de autocorrección:

1. **Extracción** — `export function <name>` en el código, `` `identifier` `` en los docs.
2. **Detección de staleness** — una referencia que no está en el conjunto de símbolos es stale
   (set-difference).
3. **Autocorrección por rename** — si el nombre viejo está en el diff de renames, se reemplaza;
   si no, se marca para revisión humana (eliminación).

## Decisiones de diseño

<Tradeoff title="El rename diff es la señal de autocorrección">
Detectar staleness es un set-difference; corregirla requiere saber el nombre nuevo, y eso solo
lo da el diff del commit. Las eliminaciones se marcan, no se adivinan.
</Tradeoff>

<Tradeoff title="Backticks como gramática de referencia">
El demo parsea spans `` `identifier` `` — un subconjunto honesto de cómo los docs referencian
símbolos — e ignora `code(id)` a propósito para evitar falsos positivos.
</Tradeoff>

<Tradeoff title="Self-healing = abrir un PR, no reescribir en su sitio">
El demo produce el contenido corregido como el cambio propuesto; producción lo envuelve en un
pull request para revisión.
</Tradeoff>

## Estado actual

Demo funcional end-to-end: 6 tests de Vitest (TS) y 4 de pytest (Python), ambos contra los
fixtures compartidos `detection.json`. Deployable en Vercel sin claves. Para producción:

- GitHub Action que lee el diff real y abre el PR de corrección
- Detección de símbolos en prose y enlaces, no solo backticks
- Corrección de firmas (no solo nombres) cuando cambian los parámetros

## Lo que demuestra

Que mantener la documentación al día es un problema de diff, no de disciplina: extraer los
símbolos del código y comparar con lo que los docs referencian convierte un doc obsoleto en una
corrección automática — y deja claro el límite, porque solo se autocorrige lo que el diff
explica.
