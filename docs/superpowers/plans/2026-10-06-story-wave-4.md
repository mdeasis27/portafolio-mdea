# Story Pages Wave 4 Implementation Plan

> **For agentic workers:** execute natively (Manuel chose native for the rollout). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn evidencia, grafo, fabrica, vigia and traductor ("find and cite information") into story pages built like Compuerta's, each with a bet a visitor can lose. Last wave: closes 21/21.

**Architecture:** Same page and shared pieces as Waves 1–3 (`pnpm brand:sync` from the hub; all five lack `outcome-tape`, `project-story`, `flow-diagram`, `copy-lint`). Each engine already works over a committed set (questions, resolution cases, logs, documents), so the tape is the engine's own items. One slider per page grades that set.

**Tech Stack:** Next.js 16, TypeScript strict, Tailwind v4, vitest. All five have a Python `backend/`; Python changes only where the engine changes (evidencia coverage, grafo hop cap, fabrica per-item status), pinned by shared fixtures read by both suites.

**Spec:** `docs/superpowers/specs/2026-10-04-project-story-pages-design.md`. Master plan: `2026-10-05-story-pages-rollout.md`. References: `../arbitro`, `../veredicto`, `../escaneo`.

## Global Constraints

- Prerequisites on `main`: backup PR #1 of each of the 5 repos (merged 2026-10-06). Branch per repo: `feat/story-page` from `origin/main`. Hub branch: `feat/story-wave-4`.
- Page order, copy rules, `why.text = ""`, `lintStory` clean, no brands, no `any`/`@ts-ignore`: as in Waves 1–3. No "not X but Y" / "no solo" / "más allá de" constructions (the lint misses them; check by hand).
- Old controls (textareas, presets, checkboxes) leave the page. Existing adapters, API routes and their tests stay unchanged except for the bug fixes below.
- Every engine change is pinned in both TS and Python by a byte-identical fixture.
- A classifier deny is a wall: stop and report BLOCKED.

## Review Focus

1. **Bet that can't lose:** a sweep test per project over its slider proving both answers, and the default answer in the table.
2. **Bet text out of sync:** `question(value)` names the slider value; the grade reads the same quantity.
3. **Tape vs result:** final tape counts equal the engine counts.
4. **Parity:** every new fixture byte-identical in TS and Python and read by both suites; Python accepts `None` where TS accepts `undefined`.
5. **Honesty:** "For engineers" names TS-only parts and synthetic data (vigia snapshot).
6. **Mobile:** 390px, no horizontal overflow.
